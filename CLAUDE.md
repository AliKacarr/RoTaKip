# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

RoTaKip is a group reading-tracker web app: an Express 5 + MongoDB/Mongoose **modular monolith** with a Vanilla JS client (no framework, no bundler beyond a custom minify script). Node 22.x. User-facing text, routes, commit-adjacent docs and many test names are Turkish; code identifiers and file names are English. `docs/architecture.md` is the authoritative (Turkish) architecture/conventions doc.

## Commands

```bash
npm install            # postinstall also runs build:assets
npm run dev            # builds assets, then node --watch src/server/start.js
npm start              # production start (does NOT rebuild assets)
npm run build:assets   # regenerate public/*.min.{js,css} + public/assets-manifest.json
npm test               # node --test; auto-discovers tests/**/*.test.js
node --test tests/unit/server/reading-edit-policy.test.js   # single file
node --test --test-name-pattern="app.js" tests/unit/server/architecture.test.js  # single test
npm run lint           # eslint . (lint:fix to autofix)
```

Requires a `.env` (see `.env.example`): `MONGO_URI`, `DB_NAME`, `SESSION_SECRET` are essential; Dropbox, OneSignal and ERP (Google Sheets) keys are optional — uploads/push/ERP sync depend on them. `SITE_ACTIVITY_ADMIN_GROUP_ID` (default `catikati23`, must pass `isSafeGroupId`) selects the group whose `admin`-authority members can open the admin/log pages (`requireSiteActivityAdmin`). `TEFEKKUR_KURAN_RADYO_URL` / `TEFEKKUR_RISALET_RADYO_URL` are the live radio stream URLs (prefer `https://`; empty → that radio shows as unavailable).

## Language

- Always converse, explain and plan with the user in natural, fluent Turkish.
- Keep code identifiers (variables, functions, file names) in English; write user-facing UI text and error messages in Turkish. In user-facing text the çetele "fields" (`ceteleFields`) are called **alışkanlık** (habit), never "alan" (code identifiers keep `field`).

## Server architecture (`src/server/`)

- `start.js` is the process entry: connects DB, creates indexes, starts Dropbox init, schedules jobs (`jobs/schedulers.js`), listens, and handles graceful shutdown.
- `app.js` is a thin **composition root**: it builds services/middleware and spreads them all into a single `routeDependencies` object passed to every `registerXRoutes(app, deps)` function. To expose a new service to routes, add it to that object rather than `require`-ing across modules.
- `tests/unit/server/architecture.test.js` enforces: `app.js` ≤ 250 lines, no direct `app.get/post/...` in `app.js`, route files must be named `*.routes.js`, and `package.json` `main`/`start`/`dev` must stay as they are.
- Feature modules live in `modules/<feature>/` split as `*.routes.js` (HTTP), `*.service.js` (business rules), `*.models.js` (Mongoose). Modules must not call another feature's routes file. External APIs only under `integrations/` (dropbox, erp, onesignal, geocoding). Framework-free helpers in `shared/`.
- Current modules: `activity` (site/access/login activity logs; allowed action names and Tefekkür/Videolar section values are validated in `activity.service.js`), `announcements` (group announcements in `announcements_<groupId>`; members' unread state is `lastSeenAnnouncementAt` on the group user; client `okumalar-announcements.js`: megaphone left of `#okumalarInfoButton`, unread banner on Bugün, admin form in the same sheet / Yönetim › Duyurular), `auth`, `cetele` (per-group daily routine form; `ceteleService` created in `app.js`), `content`, `groups`, `inspiration` (vecize/quotes + `tefekkur.routes.js`/`tefekkur.service.js`), `invitations`, `join-requests`, `pages`, `readings`, `system`, `tesbihat` (prayer times; uses `integrations/geocoding/reverse-geocoder.js`), `users`. Services such as `tefekkurService`/`tesbihatService`/`ceteleService` are created in `app.js` and spread into `routeDependencies`.
- **Per-group collections**: each group's users, reading statuses, çetele entries and announcements are stored in dynamically created collections `users_<groupId>` / `readingstatuses_<groupId>` / `cetele_<groupId>` / `announcements_<groupId>` via `getGroupCollections(groupId)` in `modules/groups/group.models.js`. Group metadata is in the shared `UserGroup` model. Always validate group ids with `isSafeGroupId` before using them in collection names.
- **ERP groups** (`sko-ekip-a|b|c|d`, `sko-towards-eternity`): a Google Form → Sheets ("Form Yanıtları 1", A:K) is synced by `integrations/erp/erp-readings-sync.js` (on group page open) and its byte-identical copy `render-worker/jobs/erpReadingsSync.js` (every 15 min; `render-worker/` is a separate repo/deploy, only the dotenv path differs — keep both in sync). Users are matched by name (`toComparableKey`); latest row per person+day wins. Column G (Risale hours) → reading field `risale` (dakika, `readingstatuses_`); D/E/F/H/I/J → `ERP_CETELE_FIELDS` keys `kuran/tesbihat/cevsen/hizmet/gorevler/namaz` in `cetele_`, written only for keys active in the group's `ceteleFields` and only when values differ. **Last writer wins**: `readingstatuses_`/`cetele_` rows carry `updatedAt` (site: write time, ERP: form submission time); `planDay` skips a day when the site wrote after the form. `scripts/import-erp-history.js [--dry-run]` set up those fields and imported the whole sheet history once (idempotent; readings insert-missing only).
- Route registration order in `app.js` matters: protected page routes are registered before static file serving.

## Client architecture

- Express serves `public/app-shell.html` for group/content routes. `public/app/` contains native ESM modules loaded directly by the browser (not bundled): `shell-router.js` resolves the URL using `route-config.js` (`ROUTES` + `ROUTE_ASSETS`), loads the view HTML from `public/fragments/`, then lazy-loads the route's bundle via `assets-manifest.json`.
- Routes: `/grup/:groupId/` (okumalar), `/gruplar` (group directory; the bottom-nav Okumalar item opens the last visited group, or this directory if none), `/tesbihat`, `/videolar`, `/tefekkur`, `/makaleler`. Legacy `/groupid=:groupId` redirects to the canonical group URL.
- Feature source lives in `src/client/features/<feature>/` (JS + CSS together), shared code in `src/client/shared/`, shell styles in `src/client/shell/`. These are classic (non-module) scripts concatenated into bundles sharing globals.
- `scripts/build-assets.js` defines the bundle → source file mapping (`shell`, `group-common`, `okumalar`, `statistics`, `management`, `videos`, `tefekkur`, `articles`, etc.). **Adding a new client file requires adding it to a bundle there** (and to `ROUTE_ASSETS` if it's a new route bundle). Bundles with an `html` list also get their `?v=<hash>` references rewritten in those HTML files — this is why commits touch `public/*.html` versions after CSS changes.
- Generated `public/*.min.js|css` and `assets-manifest.json` are gitignored; never edit them by hand. Edit sources in `src/client/`, then rebuild.
- `admin.html`, `access-logs.html`, `login-logs.html` are standalone entry documents (bundles from `features/site-activity-admin/` and `features/activity-logs/`); they are not part of shell routing/preloading.
- `/tefekkur` is a single route; sections and reading modes are chosen via query params (`?bolum=ayet|hadis|dua|risale|esma|zikirmatik|ilahi|kuran-radyo|risalet-radyo|kaydedilenler`, `?bolum=risale&mod=metin|resim`). Client sources are `src/client/features/tefekkur/tefekkur-*.js|css` (order inside the `tefekkur` bundle in `build-assets.js` matters: `core` → `share` → `slider` → `zikirmatik` → `radio` → `favorites` → `ilahi-queue` → `ilahi-player` → `ilahi` → `tab`); the star left of the Metin/Resim switch saves cards to `localStorage` (`tefekkur-favorites.js`); `?bolum=kaydedilenler[&mod=<bölüm>]` reopens them in the same swipeable slider (type filter button instead of the mode switch); API is `/api/tefekkur/*`; Esmaül Hüsna data is `public/esmaulhusna.json`. `?bolum=ilahi` is a shuffled YouTube ilahi playlist (`ilahiler` collection filled by `scripts/import-ilahiler.js`, API `/api/tefekkur/ilahiler|ilahi-onerileri`); its iframe lives in a persistent body-level stage that docks as a draggable mini player and is destroyed when a radio starts or the Videolar tab opens. Section views are logged as `tefekkur_bölüm_görüntüleme`, and `shell-router.js` does not repeat the "tab opened" log on in-tab switches. See the Tefekkür section in `docs/architecture.md`.
- `/videolar` is a single route with four views chosen by query params: feed (default; channel filter is a combobox after the section tabs (default "Tümü"), muted autoplay preview with seek bar, Shorts shelf; leaving the watch page keeps the video in a bottom-right mini player), `?izle=<videoId>` watch page, `?bolum=shorts[&v=<id>]` vertical auto-playing Shorts, `?bolum=hesabim[&liste=gecmis|begenilenler|kaydedilenler|kanallar]` library (the Geçmiş/Beğenilenler/Kaydedilenler list pages have a Turkish-folded search box and Tümü/Videolar/Shorts filter chips; Geçmiş's ⋮ at the end of the chip row pauses watch history (`historyPaused`: nothing is recorded, not even progress/"watched") or clears it; Shorts show as a horizontal shelf per day, or a grid under the Shorts chip). No modal. Data comes from the externally filled `videolar` / `video_channels` collections via `modules/content/video.service.js` (`/api/videos/home|feed|channels|:videoId`, cursor pagination). Likes, saves, watch history/progress, subscribed channels (none by default; their videos fill `SUBSCRIBED_SHARE` (currently 50%) of each feed page via `include=` and a two-part cursor) and "Bu kanalı önerme" hidden channels (`exclude=`) live only in `localStorage` (`videos-store.js`); unsubscribing asks for confirmation in a small body-level dialog. Client sources are `src/client/features/videos/videos-*.js|css` (bundle order `core` → `store` → `player` → `feed` → `watch` → `shorts` → `library` → `tab`); one reused YouTube IFrame player per section, disposed when the shell detaches the view. See the Videolar section in `docs/architecture.md`.
- `/makaleler` has a category-card home view and a per-category view (`?kategori=<slug>`; slugs/names live on the cards in `fragments/articles.html` and must match `articles.category` in Mongo). No "load more" button: `GET /api/articles/preview` prepares the first few articles of every category (and their images) when the tab opens/warms, the category view fades in once those are ready, and the rest loads on scroll via `GET /api/articles?category=&offset=&limit=` (`modules/content/article.service.js`). A search box above the category grid calls `GET /api/articles/search?q=` (in-memory, Turkish-folded, ranked; returns highlight ranges). See the Makaleler section in `docs/architecture.md`.
- The group page (`/grup/:groupId/`) renders at device width and has three sections via `?bolum=bugun|grup|yonetim` (`okumalar-tab.js`; legacy `tablo|istatistik|siralama` map to `grup`; `shell-router.js` switches sections in place on same-group popstate). There is no weekly table and no tracking-mode choice: every group uses one daily çetele form. `UserGroup.ceteleFields` holds at least one field and **the first active field is the reading field** (default "Kitap okuma", unit `sayfa|dakika` = group `amountType`); its value lives in `readingstatuses_<groupId>` (so old reading history, leagues, streaks, ranking and `/api/update-status` all use it), other admin-added fields (Kur'an, Cevşen…) live in `cetele_<groupId>`. `PUT /api/cetele/:groupId/entry` is partial (only sent keys change, `null` deletes). Bugün (`okumalar-today.js`) = big number input + quick chips for the reading field, other fields, Özetim (streak/league/30-day SVG chart, daily gift/video buttons) (no "group today" card on Sayfam) and, below them, the personal charts "İstatistiklerim" (`#okumalarMyStats`, rendered by `analytics/okumalar-stats.js`: summary tiles, last 7 days, weekly reading line, weekdays, "Alışkanlık takvimi" (habit select; same component as on Grup but the member is fixed; tapping a day opens the daily form; share), other habits, last-year heatmap, badges); no guest login card. Grup = Sıralama (`analytics/user-cards.js`; modes Bugün (who read today, unread last; admins open a member sheet → "Günlük kayıt" to fill their day) / Bu ay / Geçmiş aylar (month select) / Toplam) + Grup mesajları card (`#okumalarMessages`, directly after the ranking) + Grup istatistikleri (`analytics/okumalar-stats.js`: group tiles, "Alışkanlık takvimi" (same `habitCalendarCard` component with member + habit selects and month arrows; own days and, for admins, everyone's days open the daily form; days older than the çetele store's 63 days are fetched per month via `/api/cetele/:groupId?from&to`), weekly participation line, weekdays; no Grup/Kişi switch — personal charts live on Sayfam, and the ranking member sheet's "İstatistikler" opens them in a bottom sheet), plain SVG/CSS, rendering deferred while hidden; legacy entry points (`loadUserCards`, `loadReadingStats`, …) just schedule that render. Yönetim = "Günlük alanlar" (`cetele-settings.js`) + `group-management.js` logic/IDs moved into bottom sheets by `okumalar-manage.js`. Lig/seri math lives only in `features/groups/reading-metrics.js`; shared edit-policy/session helpers are in `okumalar-core.js` (`loadTrackerTable` is kept only as a refresh alias). Client data layer: `cetele-store.js` (`window.RoTaKipCetele`). See the Okumalar section in `docs/architecture.md`. Bugün form edits are drafts (`form.drafts`) saved/cleared with the Kaydet/Temizle buttons (`RoTaKipCetele.setValues`); `ceteleFields[].required` fields must be filled (client check + server `REQUIRED_FIELDS_MISSING`). Admins pick the hero background (`UserGroup.heroTheme`, `#okumalarHero[data-hero-theme]`, `hero-theme-settings.js`).
- Route-specific markup belongs in its `public/fragments/<route>.html`; group login/profile overlays live in `common-overlays.html` (loaded only on group routes).

## Conventions enforced by tests/lint

- `tests/integration/client/app-shell.test.js` asserts concrete markup, CSS values, and structure of the shell/fragments (e.g. nav item count/order, unique DOM ids across fragments, specific colors). UI changes often require updating these assertions.
- CSS `@media (max-width: …)` breakpoints must be one of **1023, 768, 640, 480** px.
- Files/folders use `kebab-case` with descriptive names (no generic `script.js`, `style.css`, `index.js`).
- ESLint: `public/app/**` is ESM with `no-undef` as error; other client code is `script` mode with `no-undef` off; server code is CommonJS. Unused args prefixed with `_` are ignored.
- Terser strips `console.log/debug/info` from client bundles; use `console.warn/error` for anything that must survive in production.
